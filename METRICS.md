# Metric contracts

`compute_<name>` functions are exported by `avid_benchmark.evaluation`. `METRICS` maps the CLI name to the same function. Scoring never trains a baseline or downloads an encoder.

- `compute_pixcorr(predictions, references, sample_ids=None)` and `compute_ssim(...)`: RGB float arrays `[N,3,H,W]` in `[0,1]`, 425px bilinear resize without antialias. Pearson pixel correlation returns 0 for constant images. SSIM uses grayscale, Gaussian weights, sigma 1.5, population covariance, data range 1.
- `compute_inception_2way`, `compute_clip_i_2way`, `compute_alexnet_2_2way`, `compute_alexnet_5_2way`: paired feature arrays `[N,D]`, Pearson feature similarity, strict target > each distractor. Ties fail. CLI encoders preserve historical resize/normalization (Inception 342px; CLIP-I 224px; AlexNet 256px at features.4/features.11). `compute_alexnet_2way` is retained for precomputed features with a caller-defined layer. EfficientNet correlation distance uses B1 avgpool at 255px; SwAV uses ResNet50 avgpool at 224px. All vision weights load from existing local files.
- `compute_clip_t_2way`, `compute_siglip_2way`, `compute_altclip_2way`: aligned `image_embeddings`, `text_embeddings`, cosine similarity and strict 2-way. R@1/R@5 use stable candidate order for exact ties and retain requested/effective K.
  SigLIP text extraction uses `padding="max_length"`, `max_length=64`, and `truncation=True`, consistent with the [official SigLIP preprocessing guidance](https://huggingface.co/docs/transformers/model_doc/siglip). Earlier versions used dynamic padding (`padding=True`), which made the same caption's features depend on the other captions in its batch and on batch size. **Regenerate those SigLIP text embeddings and recompute affected SigLIP scores**; changing the scoring function alone cannot repair precomputed features. This SigLIP correction preserves its image preprocessing and cosine/strict 2-way scoring. The separate canonical CLIP protocol is described below.
- `compute_tifa(question_scores, sample_ids=None)`: each stimulus has a nonempty list of fixed-question VQA/SBERT scores. Average within stimulus, then across stimuli. `EncoderPool.tifa` reuses VQA/SBERT models and reads the frozen question bank.
- Attribute functions take answer rows containing `attribute`, `image_name`, `question_id`, `answer` (canonical grouping label), `acceptable_answers`, `choices`, and `mapped_answer`. Missing/unrecognized answers score 0. Balanced accuracy averages recall across observed canonical answer classes. Balanced chance uses the same groups and each question's `len(acceptable_answers)/len(choices)`. Repeated images from different participants must be scored separately.
- Caption functions take nonempty aligned lists `predictions`, `references`. The historical tokenizer lowercases ASCII alphanumeric words and retains punctuation and each non-ASCII character. Historical BLEU adds 1 to numerator/denominator and treats absent higher-order n-grams as precision 1. Empty prediction is zero. ROUGE-L uses longest common subsequence F1. Token-F1 uses multiset overlap. Reference source must be declared (provided GT vs deterministic target-embedding captions); they are different experiments.

Nonfinite inputs and duplicate sample IDs are errors. Scores record the full denominator and protocol. Extraction failure is an evaluation failure; it must not be converted to NaN and labelled computed. No persistent evaluator cache is reused without provenance; the CLI only shares in-memory features within one fixed evaluation run.

## CLIP evaluation protocol

All four reconstruction baselines use the same **OpenAI CLIP ViT-L/14** evaluation encoder for `clip_i_2way`, `clip_t_2way`, `clip_t_recall_at_1`, and `clip_t_recall_at_5`. Set `evaluation.clip` to the original local OpenAI `ViT-L-14.pt` file from [Asset downloads](docs/ASSETS.md#evaluation-assets). The evaluator verifies the fixed checkpoint SHA-256 before loading it with the native `clip` API (`clip-anytorch==2.6.0`, `jit=False`). A Hugging Face model directory or ViT-B/32 checkpoint is an error. Baseline training/generation CLIP and OpenCLIP assets remain separate configurations.

- **Images:** both CLIP-I and CLIP-T/retrieval consume the same generated-image features: RGB float tensors in `[0,1]`, resized directly to `224 x 224` with bilinear interpolation, `align_corners=False`, and `antialias=False`; then normalized with mean `[0.48145466, 0.4578275, 0.40821073]` and standard deviation `[0.26862954, 0.26130258, 0.27577711]`. Use this raw-tensor path for reference images too. Do not substitute the default processor's bicubic resize/center crop. Generated-image features are reused across these metrics within each participant candidate set.
- **Text:** native OpenAI `clip.tokenize`, context length 77, `truncate=True`, followed by `encode_text`. Scores use the existing Pearson feature similarity for CLIP-I and cosine similarity for CLIP-T/retrieval; strict 2-way/tie rules are unchanged.
- **Batch/precision:** `evaluation.clip_batch_size` defaults to **160**, independently of other encoders' `evaluation.batch_size`. This is the calibrated setting used by the unified paper evaluation. Native loading retains CUDA mixed precision (FP16 compute with FP32 LayerNorm); do not apply `model.half()` to every layer. CPU loading uses FP32 for validation and may give small numerical differences from the CUDA paper runs. Changing batch size may also alter floating-point results; record any override. The previous historical controls retained a maximum CLIP difference of about 0.0475 percentage points after calibration, rather than claiming bitwise reproduction.
- **Provenance:** prediction-based reports include `encoder_protocols.clip` with checkpoint hash, implementation, dtype, device, batch size, resize, antialias setting, token context, and preprocessing policy. The checkpoint is read only from an existing local file; no download is initiated.

Earlier templates pointed at Hugging Face ViT-B/32, and the CLIP-T branch used a different image-preprocessing path from CLIP-I. Update both templates and the local `evaluation.clip` setting, install the evaluation extra, and regenerate any CLIP embeddings/scores produced under that older setup before comparing them with the unified paper protocol. Matching the encoder alone does not establish that image bytes, captions, sample order, or precision match a prior run. Array-only scoring functions remain encoder-independent; callers supplying precomputed arrays must establish and report the matching extraction protocol themselves.
